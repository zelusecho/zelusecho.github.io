Course reflection

ICS4U learning.

This page shows the main concepts I worked on in ICS and how my coding improved over the course. I wanted this section to feel clear, honest, and connected to what I actually learned.

Topics covered

What I learned,
step by step.

Assignment connection: I practiced OOP through the employee assignment, where each employee had names, a birth date, and a hire date instead of everything being stored loose in one main method.

What I learned: OOP helped me understand that a program can be broken into smaller pieces. A class is like the blueprint, and the object is the actual thing made from it.

What I struggled with: At first, I wanted to put everything inside one file because that felt easier. The hard part was understanding why private variables, constructors, and methods make the program cleaner later.

Why it matters: Engineering and programming both need structure. OOP matters because bigger projects only stay manageable when each part has a clear job.

public class Employee {
    private String firstName;
    private String lastName;
    private Date birthDate;
    private Date hireDate;

    public Employee(String first, String last,
                    Date dateOfBirth, Date dateOfHire) {
        firstName = first;
        lastName = last;
        birthDate = dateOfBirth;
        hireDate = dateOfHire;
    }
}

Assignment connection: I used arrays in the computer comparison program to store computer names, GPUs, CPUs, RAM, battery life, and year made.

What I learned: Arrays made me see how one index can connect related pieces of data. For example, index zero in each array represents the same computer.

What I struggled with: The hardest part was keeping the indexes lined up. If one array was in the wrong order, the computer name could match the wrong RAM or GPU, which would ruin the output.

Why it matters: Arrays are basic, but they build the foundation for almost everything else in ICS. They taught me how to organize repeated data instead of writing the same code over and over.

Assignment connection: I also worked with 2D arrays in the computer assignment. Instead of separate arrays for every category, I stored related computer information in rows.

What I learned: A 2D array felt like a table. One row could store names, another row could store GPUs, and another row could store CPUs.

What I struggled with: I struggled with remembering what each row meant. The code worked better once I started commenting the rows clearly, because otherwise computers[2][i] was easy to mix up.

Why it matters: 2D arrays are useful when data has categories. This made me think more about how information is organized before I even start coding.

Assignment connection: I used ArrayLists in my Bridge program to create a deck, store player hands, remove cards while dealing, and calculate points.

What I learned: ArrayLists felt more flexible than arrays because I could add and remove items while the program was running. That made sense for a card game because the deck changes every time cards are dealt.

What I struggled with: I struggled with removing from index zero because every remove shifts the list. I had to slow down and think about how the deck changes after every card is dealt.

Why it matters: ArrayLists are important because real programs usually do not know exactly how much data they will need. They made my code feel more realistic.

Assignment connection: I used searching in the student marks program to prevent duplicate student numbers and to find one student by name or student number.

What I learned: Searching taught me that a program has to check data carefully instead of assuming the user entered something valid.

What I struggled with: The part I struggled with was not just finding the match, but also handling what happens when the match does not exist. A good program needs a clear not found result too.

Why it matters: Searching is one of the most practical skills in programming because almost every app needs to find information quickly and accurately.

public boolean exists(String num) {
    for (int i = 0; i < numbers.size(); i++) {
        if (numbers.get(i).equals(num)) {
            return true;
        }
    }
    return false;
}

Assignment connection: In the student marks program, I sorted student information alphabetically and also sorted by average mark. I used index arrays so I could sort without destroying the original data.

What I learned: Sorting showed me that organizing data is not just about making it look nice. It makes the information easier to read, compare, and use.

What I struggled with: I found the index array idea confusing at first because I was not sorting the names directly. I was sorting the positions that pointed to the names, which took more thinking.

Why it matters: Sorting matters because raw data is messy. Once it is sorted, patterns become easier to see.

Integer[] indices = new Integer[names.size()];
for (int i = 0; i < indices.length; i++) indices[i] = i;

for (int i = 1; i < indices.length; i++) {
    Integer key = indices[i];
    int j = i - 1;

    while (j >= 0 && names.get(indices[j])
            .compareToIgnoreCase(names.get(key)) > 0) {
        indices[j + 1] = indices[j];
        j--;
    }
    indices[j + 1] = key;
}

Assignment connection: I practiced recursion through programs that found sums, powers, counted characters, found the greatest common divisor, and even found a lowest cost path in a grid.

What I learned: Recursion helped me understand that a big problem can sometimes be solved by solving a smaller version of the same problem.

What I struggled with: This was one of the harder topics for me. The method calling itself felt strange at first, and I had to trace the calls by hand before the base case finally made sense.

Why it matters: Recursion matters because it teaches a deeper type of problem solving. It forced me to think about patterns, not just loops.

public static int gcd(int a, int b) {
    if (b == 0) {
        return a;
    }
    return gcd(b, a % b);
}

public static int count(String s, char c) {
    if (s.length() == 0) return 0;
    if (s.charAt(0) == c) return 1 + count(s.substring(1), c);
    return count(s.substring(1), c);
}

Assignment connection: I used file output in the student marks program so the program could save regular data and sorted data into text files.

What I learned: File output showed me that a program can create results that last after the program closes. That made the assignment feel more complete and useful.

What I struggled with: I struggled with remembering the try and catch structure and making sure the file was closed properly. It was also easy to forget that saving sorted data needed a separate method.

Why it matters: File I/O matters because real software has to store information. Without saving, the program loses everything once it stops running.

public void saveToFile() {
    try {
        FileWriter fw = new FileWriter("students.txt");
        PrintWriter out = new PrintWriter(fw);

        for (int i = 0; i < names.size(); i++) {
            out.println(names.get(i) + "," + numbers.get(i));
        }

        out.close();
    } catch (IOException e) {
        System.out.println("Error saving data to file.");
    }
}

Assignment connection: The Bridge program helped me practice algorithm design because it had clear steps: create the deck, shuffle it, deal cards, calculate points, compare scores, and print a winner.

What I learned: I learned that coding is easier when I know the plan first. Once the steps are clear, the code becomes less random and more like building one piece at a time.

What I struggled with: I struggled with making sure the score calculation matched the rules. The program had to count ranks, count suits, add extra points, and then compare all four players fairly.

Why it matters: Algorithm design matters because it is the difference between guessing and actually solving the problem. It is probably the biggest skill I improved in ICS.
