Assignment connection: I used classes in a student information or address book style assignment where each object stored related pieces of data together.

What I learned: OOP helped me understand how programs become easier to manage when data and behaviour are grouped into a class.

What I struggled with: At first, I mixed up instance variables, parameters, and local variables, especially when using this.

What I enjoyed: I liked that OOP made the program feel more realistic and organized instead of having everything in one large method.

Why it matters: Larger programs become easier to read, update, and expand when they are built with classes and objects.

Assignment connection: Arrays were useful in assignments where I needed to store several values of the same type, such as marks, names, or numbers.

What I learned: Arrays store multiple values using indexes, and loops are usually needed to process them efficiently.

What I struggled with: Remembering that indexes start at 0 and avoiding ArrayIndexOutOfBoundsException.

What I enjoyed: Arrays made it easier to work with many values at once instead of writing many separate variables.

Why it matters: Arrays are one of the basic data structures, so understanding them makes advanced structures easier later.

Assignment connection: Searching appeared in programs where the user had to find a student, a mark, or another item inside a collection.

What I learned: Linear search checks each value one by one, while binary search is much faster but only works on sorted data.

What I struggled with: Loop conditions and returning the correct index or message when the item was not found.

What I enjoyed: Searching felt satisfying because it connected logic directly to a useful task in a program.

Why it matters: Programs often need to retrieve information quickly and correctly.

CUSTOMIZE THIS: Add your own assignment or practice problem where you searched through data.

public static int linearSearch(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) {
        if (nums[i] == target) {
            return i;
        }
    }
    return -1;
}

What I learned: Sorting algorithms repeatedly compare values and move them into the correct order.

What I struggled with: Following nested loops and understanding exactly when the swap should happen.

What I enjoyed: It was interesting to see how a small amount of code could reorganize a list.

Why it matters: Ordered data is easier to analyze, search, and present to the user.

for (int i = 0; i < nums.length - 1; i++) {
    for (int j = 0; j < nums.length - 1 - i; j++) {
        if (nums[j] > nums[j + 1]) {
            int temp = nums[j];
            nums[j] = nums[j + 1];
            nums[j + 1] = temp;

    }

Assignment connection: Recursion appeared in problems like factorials, hailstone sequences, or methods that repeated a pattern until a base case was reached.

What I learned: Recursion needs a base case that stops the method and a recursive case that moves closer to the base case.

What I struggled with: It was easy to read the code line by line but harder to picture the repeated method calls.

What I enjoyed: I liked how short and elegant a recursive solution could be once I understood it.

Why it matters: Recursion builds problem solving skills and shows another way to approach repeated patterns.

CUSTOMIZE THIS: Replace with the recursive example that made the most sense to you.

public static int factorial(int n) {
    if (n == 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
